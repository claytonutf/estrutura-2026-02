01 · Conceito

O que é recursividade?

Recursão é uma técnica em que uma função chama a si mesma, direta ou indiretamente, para resolver um problema por meio de instâncias menores ou mais simples.

🧩

Divida o problema

Transforme o problema original em uma versão menor do mesmo problema.

🛑

Defina o caso base

É a condição de parada. Sem ela, as chamadas podem continuar indefinidamente.

↩️

Deixe a pilha trabalhar

As chamadas são empilhadas. Ao chegar ao caso base, os resultados retornam na ordem inversa.

Analogia: pense em dois espelhos frente a frente: cada imagem parece gerar outra. Em um algoritmo recursivo, porém, precisamos de uma condição que interrompa o processo.
02 · Anatomia

As duas partes essenciais

Uma função recursiva bem formada possui uma condição de parada e uma chamada que aproxima o problema do caso base.

1

Caso base

A solução mais simples, conhecida diretamente.

2

Caso recursivo

A função chama a si mesma com uma entrada menor ou mais simples.

3

Progresso

Cada chamada deve caminhar em direção ao caso base.

4

Retorno

Depois do caso base, as chamadas são resolvidas de trás para frente.

Modelo mental

tipo funcao(entrada) { se (caso_base) retorne solução; retorne funcao(entrada_menor); }

Checklist antes de executar

  • Qual é o caso base?
  • A entrada realmente se aproxima dele?
  • O que cada chamada precisa retornar?
  • Quantas chamadas ficam simultaneamente na pilha?
03 · Call Stack

A pilha de chamadas

Cada chamada de função cria um novo quadro (stack frame), contendo informações necessárias para continuar a execução. Quando o caso base é atingido, a pilha começa a ser desempilhada.

Descendo ↘

As chamadas se acumulam:

f(5) └─ f(4) └─ f(3) └─ f(2) └─ f(1) ← caso base

Subindo ↗

Depois do caso base, cada chamada retoma e retorna seu resultado:

f(1) → resultado ↑ f(2) ↑ f(3) ↑ f(4) ↑ f(5)

Por que isso importa?

A recursão consome espaço na pilha. Quanto mais profunda a recursão, mais quadros ficam ativos simultaneamente.

Stack overflow: pode ocorrer quando a recursão não termina ou quando a profundidade ultrapassa o espaço disponível para a pilha.
Armadilha clássica: criar um caso base que nunca será alcançado. Ex.: começar em 10 e testar uma condição que exige chegar a 100 por decrementos.
04 · Exemplos em C

Recursividade na prática

Fatorial

Matematicamente: n! = n × (n−1)!, com 0! = 1.

int fatorial(int n) { if (n == 0) { return 1; } return n * fatorial(n - 1); }
Exemplo:
5! = 5 × 4 × 3 × 2 × 1 = 120

As chamadas descem até fatorial(0) e depois retornam.

Fibonacci

A sequência começa com fib(0)=0 e fib(1)=1; para n ≥ 2, fib(n)=fib(n−1)+fib(n−2).

int fib(int n) { if (n == 0) { return 0; } if (n == 1) { return 1; } return fib(n - 1) + fib(n - 2); }
Observe: a versão recursiva ingênua repete muitos cálculos. É um ótimo exemplo para discutir custo computacional e memoização.

Contagem regressiva

void contagem(int n) { if (n <= 0) { return; } printf("%d\n", n); contagem(n - 1); }

O caso base é alcançado quando n chega a 0. É um exemplo simples para visualizar a profundidade da pilha.

Soma dos primeiros n naturais

int soma(int n) { if (n == 1) { return 1; } return n + soma(n - 1); }

Para n = 5: 5 + 4 + 3 + 2 + 1 = 15.

06 · Quando usar?

Recursão ou iteração?

RecursãoIteração (laços)
Pode deixar estruturas hierárquicas mais naturais de expressar.Frequentemente usa menos espaço extra de pilha.
É útil em árvores, grafos, divide and conquer e backtracking.É adequada quando o problema é naturalmente sequencial.
Cada chamada acrescenta um quadro à pilha.Um laço pode evitar múltiplos quadros de chamada.
Exige atenção especial ao caso base e à profundidade.Exige atenção à condição de parada e atualização das variáveis.
Regra prática: não use recursão apenas porque é possível. Use-a quando ela tornar a solução mais clara ou quando a estrutura do problema for naturalmente recursiva.
07 · Aplicações

Onde a recursividade aparece?

🌳

Árvores

Percursos em árvores binárias e árvores de decisão são exemplos naturais.

🕸️

Grafos

DFS (busca em profundidade) pode ser implementada recursivamente ou com uma pilha explícita.

⚡

Divide and Conquer

Merge Sort, Quick Sort e implementações recursivas de busca binária são exemplos clássicos de divisão em subproblemas.

🧩

Backtracking

Permutações, combinações, labirintos e outros problemas de busca de possibilidades.

🌀

Fractais

Recorrências e regras repetidas podem gerar padrões fractais. O conjunto de Mandelbrot, especificamente, é definido por uma iteração matemática, não deve ser apresentado simplesmente como um “exemplo de recursão”.

💾

Memoização

Resultados de subproblemas podem ser armazenados para evitar recomputações.

08 · História e pessoas

Da matemática aos algoritmos

A ideia de definir objetos e funções por meio de versões menores de si mesmos é anterior aos computadores. No século XX, ela ganhou uma formulação rigorosa na lógica e tornou-se uma técnica prática de programação.

Antes dos computadores

Definições recursivas já eram usadas na matemática. O fatorial, por exemplo, pode ser definido por n! = n × (n−1)!, com 0! = 1.

Década de 1930

Kurt Gödel trabalhou com funções recursivas na lógica. Alonzo Church desenvolveu o cálculo lambda e publicou resultados fundamentais sobre computabilidade. Alan Turing apresentou seu modelo de computação em 1936–1937.

1958–1960

John McCarthy desenvolveu LISP em 1958. Seu artigo de 1960 sobre “Recursive Functions of Symbolic Expressions” ajudou a estabelecer as bases teóricas da linguagem.

Décadas de 1960–1980

Recursão tornou-se especialmente importante em algoritmos de divisão e conquista e no processamento de estruturas hierárquicas, como árvores.

Hoje

A técnica continua presente em percursos de árvores e grafos, backtracking, divide and conquer, compiladores, linguagens funcionais e diversas técnicas algorítmicas.

💡

Curiosidade: por que LISP?

Em uma entrevista de história oral, McCarthy explicou que, ao trabalhar com diferenciação simbólica, a recursão surgiu naturalmente e o FORTRAN da época não permitia o tipo de recursão de que ele precisava. Isso ajudou a motivar a criação de uma nova linguagem.

🎓

Church e Turing

Alan Turing esteve em Princeton como estudante visitante e realizou seu doutorado sob orientação de Alonzo Church. Os trabalhos dos dois ajudaram a consolidar diferentes modelos de computabilidade.

🤖

McCarthy também criou o termo “IA”

McCarthy é associado à introdução do termo artificial intelligence em 1955 e foi uma das figuras fundadoras da área.

🧠

“Recursivo” tem dois contextos

Na matemática e na teoria da computação, “função recursiva” possui um significado técnico próprio. Na programação, “função recursiva” normalmente significa uma função que chama a si mesma, direta ou indiretamente.
