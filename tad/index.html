01 · CONCEITO

De tipo de dado a tipo abstrato

Um tipo de dado define o domínio de valores e as operações que uma variável pode assumir — o char em C, por exemplo, aceita inteiros entre −128 e 127, além de soma e subtração. Esses tipos básicos não têm estrutura interna.

Quando esses valores passam a se relacionar entre si — de forma linear ou não — surge uma estrutura de dados. Vetores, structs, unions e enums em C são exemplos, todos construídos a partir dos tipos básicos.

Às vezes a linguagem não é suficiente: é preciso também decidir quais operações ficam disponíveis para manipular esses dados. É aí que entra o Tipo Abstrato de Dados.

DEFINIÇÃO

Estrutura de dados: um conjunto de tipos de dados com algum relacionamento lógico estrutural entre eles — uma forma de organizar informação para uso eficiente.

DEFINIÇÃO

Tipo Abstrato de Dados (TAD): um conjunto de dados estruturados, mais as operações — implementadas como funções — que podem ser executadas sobre eles.

O TAD é construído sobre os tipos básicos (int, char, float, double) ou estruturados (array, struct, union, enum) — mas é uma entidade teórica, usada para descrever algoritmos e sistemas, não uma feature nativa da linguagem.

02 · POR QUÊ

O que a caixa-preta compra

Tanto a representação quanto as operações de um TAD são definidas pelo programador. O usuário só enxerga a interface — nunca a implementação por trás dela.

Encapsulamento

O usuário só precisa conhecer as operações disponíveis — nenhum detalhe técnico de implementação é necessário para usar o TAD.

Segurança

Sem acesso direto aos dados, o usuário não consegue manipulá-los de forma imprópria ou inconsistente.

Flexibilidade

A implementação pode mudar sem alterar quem usa o TAD — diferentes versões podem coexistir desde que respeitem a mesma interface.

Reutilização

Implementação e uso vivem em módulos separados, prontos para serem reaproveitados em outros programas.

03 · EXEMPLO

O tipo FILE já é um TAD

Quem já trabalhou com arquivos em C já usou um TAD sem perceber: o tipo FILE. Ele guarda o nível do buffer, flags de status, o descritor do arquivo, o buffer de transferência e outros campos internos — mas ninguém deveria acessar esses campos diretamente.

A única forma correta de trabalhar com ele é declarando um ponteiro:

terminal
FILE *f;

O ponteiro f só é manipulado através das funções da interface — nunca lendo ou escrevendo seus campos diretamente.

fopen() fclose() fputc() fgetc() feof() …
Exemplo: estrutura do tipo FILE
typedef struct{
    int            level;    // nível do buffer
    unsigned       flags;    // flag de status do arquivo
    char           fd;       // descritor do arquivo
    unsigned char  hold;     // retorna caractere sem buffer
    int            bsize;    // tamanho do buffer
    unsigned char *buffer;  // buffer de transferência de dados
    unsigned char *curp;    // ponteiro atualmente ativo
    unsigned       istemp;   // indicador de arquivo temporário
    short          token;    // usado para validação
}FILE;
POR QUE ISSO IMPORTA

Diferentes bibliotecas C implementam essa struct de formas bem diferentes por baixo dos panos — e seu código continua funcionando do mesmo jeito em todas elas, porque nunca depende dos campos internos.

04 · MECANISMO

Tipo opaco: a técnica por trás

Um tipo é opaco quando fica incompletamente definido na interface — só a biblioteca conhece seu conteúdo real, e seus valores só são acessíveis por funções específicas.

FIG. 4.3interface (.h) × implementação (.c)

A técnica usa dois arquivos:

ARQUIVO .H

Declara o tipo que representa os dados ocultos e os protótipos das funções — é tudo que o usuário pode enxergar e usar, sempre por ponteiro.

ARQUIVO .C

Declara de fato o tipo de dado que fica oculto do usuário, e implementa cada uma das funções anunciadas no .h.

Com isso, o programa que usa a biblioteca só manipula ponteiros — e todo acesso real aos dados passa, obrigatoriamente, pelas funções da interface.

06 · ORGANIZAÇÃO

Modularização: dividir para conquistar

Separar a definição do TAD em dois arquivos — .h para a interface visível, .c para a implementação oculta — é chamado de modularização.

Um módulo é uma unidade com propósito único, compilável separadamente do resto do programa. Quanto maior a aplicação, mais um único arquivo se torna um problema: reutilizar vira copiar e colar, e qualquer mudança força recompilar tudo.

Dividir em módulos traz:

  • Problemas grandes viram conjuntos de problemas menores
  • Mais oportunidades de reutilização de código
  • Um programa mais fácil de entender
  • Dados e processos relacionados agrupados e encapsulados
  • Times inteiros trabalhando em arquivos diferentes ao mesmo tempo
  • Recompilação apenas do que realmente mudou
  • Verificação independente de cada módulo antes do uso
07 · NA PRÁTICA

Construindo o TAD Ponto

Um TAD que representa um ponto no plano, com coordenadas x e y, acessado sempre por Ponto* p;. Ele mostra, passo a passo, tudo o que este documento explicou até aqui.

1

A interface — Ponto.h

Define o tipo opaco Ponto e os protótipos das funções. É só o que o usuário da biblioteca precisa enxergar.

Ponto.h
typedef struct ponto Ponto;
//Cria um novo ponto
Ponto* Ponto_cria(float x, float y);
//Libera um ponto
void Ponto_libera(Ponto* p);
//Acessa os valores "x" e "y" de um ponto
int Ponto_acessa(Ponto* p, float* x, float* y);
//Atribui os valores "x" e "y" a um ponto
int Ponto_atribui(Ponto* p, float x, float y);
//Calcula a distancia entre dois pontos
float Ponto_distancia(Ponto* p1, Ponto* p2);
2

Os dados ocultos — Ponto.c

A struct real vive só aqui. Fora deste arquivo, ninguém sabe — nem precisa saber — que ela tem exatamente estes dois campos.

Ponto.c
#include <stdlib.h>
#include <math.h>
#include "Ponto.h" //inclui os protótipos
struct ponto{ //definição do tipo de dados
    float x;
    float y;
};
3

Criar um ponto

Aloca memória para a struct oculta, inicializa os campos com os valores recebidos e devolve o ponteiro — a única coisa que o usuário vai guardar.

Ponto.c
Ponto* Ponto_cria(float x, float y){
    Ponto* p = (Ponto*) malloc(sizeof(Ponto));
    if(p != NULL){
        p->x = x;
        p->y = y;
    }
    return p;
}
4

Destruir um ponto

Uma simples chamada a free() — mas encapsulada numa função própria, para que TADs mais complexos possam esconder uma destruição mais elaborada sem quebrar quem os usa.

Ponto.c
void Ponto_libera(Ponto* p){
    free(p);
}
5

Acessando o conteúdo de um ponto

A função checa primeiro se o ponteiro é válido, retornando 0 em caso de erro. Caso contrário, copia os valores para fora por referência e retorna 1.

Ponto.c
int Ponto_acessa(Ponto* p, float* x, float* y){
    if(p == NULL)
        return 0;
    *x = p->x;
    *y = p->y;
    return 1;
}
6

Atribuindo um valor ao ponto

Mesma lógica de validação, agora gravando os valores recebidos por parâmetro dentro da estrutura.

Ponto.c
int Ponto_atribui(Ponto* p, float x, float y){
    if(p == NULL)
        return 0;
    p->x = x;
    p->y = y;
    return 1;
}
7

Calculando a distância entre dois pontos

Se algum dos dois TADs for inválido, a função retorna -1 — não existe distância negativa, então esse valor sinaliza erro sem ambiguidade.

Ponto.c
float Ponto_distancia(Ponto* p1, Ponto* p2){
    if(p1 == NULL || p2 == NULL)
        return -1;
    float dx = p1->x - p2->x;
    float dy = p1->y - p2->y;
    return sqrt(dx * dx + dy * dy);
}
8

Usando o TAD

Do lado do usuário, tudo se resume a ponteiros e chamadas de função — a struct nunca aparece, e o compilador barra qualquer tentativa de declarar um Ponto por valor ou de acessar p->x diretamente.

main.c
#include <stdio.h>
#include <stdlib.h>
#include "Ponto.h"

int main(){
    float d;
    Ponto *p,*q;
    //Ponto r; //ERRO
    p = Ponto_cria(10,21);
    q = Ponto_cria(7,25);
    //q->x = 2; //ERRO
    d = Ponto_distancia(p,q);
    printf("Distancia entre pontos: %f\n",d);
    Ponto_libera(q);
    Ponto_libera(p);
    system("pause");
    return 0;
}
