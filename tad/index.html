01 · Fundamento

O que é um TAD?

Um Tipo Abstrato de Dados (TAD) define um conjunto de dados e as operações que podem ser realizadas sobre esses dados, destacando o comportamento que o usuário pode utilizar e separando-o da representação interna.

D

Dados

Representam o estado mantido pelo TAD. A forma como esses dados são armazenados pode ficar escondida.

O

Operações

São as funções que permitem criar, consultar, atualizar, inserir, remover ou destruir informações, conforme o TAD.

I

Interface

É o conjunto de elementos disponibilizados ao programa usuário para utilizar o TAD sem depender da implementação.

Abstração: o usuário trabalha com uma visão simplificada do objeto. Ele precisa saber quais operações estão disponíveis e como utilizá-las, mas não necessariamente precisa conhecer sua representação interna.

03 · Exemplo clássico em C

O tipo FILE

Ao trabalhar com arquivos em C, o programa utiliza um ponteiro para FILE e as funções fornecidas pela biblioteca padrão.

Uso pelo programa

declaração
FILE *f;

O programa não precisa manipular diretamente os campos internos de um objeto FILE. A interação ocorre por meio da interface da biblioteca.

Operações conhecidas

  • fopen() — abre um arquivo
  • fclose() — fecha um arquivo
  • fputc() — escreve um caractere
  • fgetc() — lê um caractere
  • feof() — verifica indicação de fim de arquivo
04 · Encapsulamento

Tipo opaco

Um tipo opaco é apresentado ao usuário de modo que sua representação interna permaneça escondida. O acesso ocorre por meio das operações disponibilizadas pela interface.

O que o usuário vê

typedef struct Arquivo Arquivo;

Arquivo *a;

a = arquivo_criar();
arquivo_escrever(a, ...);
arquivo_destruir(a);

O cabeçalho pode declarar apenas a existência do tipo e disponibilizar um ponteiro para ele.

O que fica escondido

struct Arquivo {
    int estado;
    char *buffer;
    size_t tamanho;
    /* detalhes internos */
};

A definição completa pode permanecer no arquivo de implementação. Assim, o código cliente não depende dos campos internos.

05 · Operações

Operações básicas de um TAD

As operações variam conforme o TAD, mas algumas categorias aparecem com frequência.

+

Criação

Inicializa uma nova instância do TAD e prepara seus recursos.

↳

Inserção

Adiciona um novo elemento ou informação ao conjunto de dados.

−

Remoção

Retira um elemento ou informação do TAD, respeitando suas regras.

?

Acesso

Consulta informações por meio das operações definidas pela interface.

↻

Atualização

Modifica o estado interno utilizando operações controladas.

×

Destruição

Libera os recursos associados ao TAD quando ele deixa de ser necessário.

06 · Organização do código

Modularização em C

Uma organização comum separa a interface da implementação em arquivos .h e .c.

arquivo.h
typedef struct Pilha Pilha;

Pilha *pilha_criar(void);
void pilha_destruir(Pilha *p);
int pilha_vazia(const Pilha *p);
void pilha_empilhar(Pilha *p, int valor);
int pilha_desempilhar(Pilha *p, int *valor);

O cabeçalho expõe o contrato: nome do tipo e operações disponíveis.

arquivo.c
struct Pilha {
    int *dados;
    size_t capacidade;
    size_t topo;
};

/* implementação das funções */

A implementação conhece a representação completa e é responsável por manter as regras do TAD.

main.c
#include "pilha.h"

int main(void) {
    Pilha *p = pilha_criar();
    pilha_empilhar(p, 10);
    pilha_empilhar(p, 20);
    pilha_destruir(p);
    return 0;
}

O programa usuário utiliza as operações sem acessar diretamente dados, capacidade ou topo.

07 · Por que modularizar?

Dividir para conquistar

À medida que uma aplicação cresce, a organização em módulos facilita a compreensão, manutenção, reutilização e evolução do software.

Dividir o problema

Um problema maior pode ser organizado em módulos menores, cada um com propósito bem definido.

Encapsular responsabilidades

Dados e operações logicamente relacionados ficam agrupados em um módulo.

Reutilizar

Um módulo pode ser utilizado por diferentes programas sem copiar toda a implementação.

Facilitar manutenção

Alterações internas podem ser realizadas sem exigir mudanças no código cliente, desde que a interface permaneça compatível.

Trabalhar em equipe

Arquivos e módulos bem definidos facilitam a divisão do trabalho entre programadores.

Principais benefícios

  • maior reutilização de código;
  • melhor organização e compreensão;
  • encapsulamento dos dados;
  • manutenção mais simples;
  • possibilidade de compilação separada;
  • verificação independente dos módulos;
  • maior confiabilidade.

Um cuidado importante

Modularização não significa simplesmente separar um programa em vários arquivos. Um bom módulo possui uma responsabilidade clara e uma interface bem definida.

Regra prática: programe contra a interface, não contra os detalhes internos da implementação.
