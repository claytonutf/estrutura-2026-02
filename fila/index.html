1. Definição

O conceito de fila, ou fila de espera, faz parte do cotidiano: enfrentamos filas no banco, no cinema e em diversos outros lugares. Na computação, uma fila é um conjunto finito de itens de um mesmo tipo que aguardam um serviço ou processamento.

Uma fila é uma estrutura de dados linear, isto é, seus elementos formam uma sequência. Diferentemente de uma lista, que permite acesso a diferentes posições conforme sua implementação, a fila estabelece uma ordem para entrada e saída: a inserção acontece em uma extremidade e a remoção na outra.

Um exemplo comum é o gerenciamento de documentos enviados para uma impressora. Em geral, o primeiro documento enviado é o primeiro a ser impresso. Filas também organizam tarefas, requisições e eventos que aguardam processamento.

Ideia central: um elemento só pode ser removido depois dos elementos que chegaram antes dele. A fila pode conter N elementos, com N ≥ 0. Quando N = 0, ela está vazia. Dependendo da aplicação, elementos repetidos são permitidos.

2. O princípio FIFO

Filas seguem o princípio FIFO (First In, First Out), que significa “primeiro a entrar, primeiro a sair”. Os elementos são removidos na mesma ordem em que foram inseridos.

Execute a operação passo a passo: a cada clique, a linha do código em destaque e os ponteiros do desenho mudam juntos.

inicio primeiro nó final último nó no ponteiro auxiliar




O nó mais à esquerda é sempre o próximo a sair (FIFO). Limite visual: 8 elementos.







3. Tipos de implementação


As duas implementações clássicas diferem pela forma de alocação da memória e pelo modo de acesso aos elementos.




Alocação estática
Acesso sequencial
O espaço é reservado previamente, geralmente em um vetor. É necessário definir a capacidade máxima, e os elementos ficam em posições consecutivas de memória.
Vantagens: estrutura simples e acesso direto por índice.
Atenção: a capacidade é limitada e a implementação precisa tratar o reaproveitamento das posições.


Alocação dinâmica
Acesso encadeado
A memória é alocada durante a execução. Cada nó armazena o dado e um ponteiro para o próximo nó, portanto os elementos não precisam estar em posições consecutivas.
Vantagens: a fila cresce e diminui conforme as inserções e remoções.
Atenção: é necessário gerenciar os ponteiros e liberar a memória usada.




Este material implementa a fila dinâmica encadeada.

    • 

  • Verificar se está vazia ou cheia: consultar o estado da estrutura.
    • 

  • Imprimir: percorrer a fila do início ao fim, mostrando os elementos sem alterá-la.
    • 

  • Destruir: liberar a memória ocupada pela fila dinâmica e por seus nós.

Antes de remover ou consultar o início, verifique se a fila não está vazia. Em uma fila encadeada, “cheia” normalmente significa que não foi possível alocar memória para um novo nó.

#ifndef FILADIN_H
#define FILADIN_H

struct aluno{
    int matricula;
    char nome[30];
    float n1,n2,n3;
};
typedef struct fila Fila;

Fila* cria_Fila();
void libera_Fila(Fila* fi);
int consulta_Fila(Fila* fi, struct aluno *al);
int insere_Fila(Fila* fi, struct aluno al);

O cabeçalho declara typedef struct fila Fila; sem mostrar o conteúdo da struct. Assim, o main.c só consegue manipular a fila pelas funções, o que protege a estrutura de alterações indevidas. Os include guards (#ifndef, #define, #endif) evitam que o arquivo seja incluído duas vezes.


Cada elemento da fila guarda os dados de um aluno (struct aluno), mas a lógica da fila não depende disso: para armazenar outro tipo de dado, basta alterar essa struct.







6. Implementação em FilaDin.c


Estruturas internas


FilaDin.c


#include <stdio.h>
#include <stdlib.h>
#include "FilaDin.h" //inclui os protótipos

//definição do tipo Fila
struct elemento{
    struct aluno dados;
    struct elemento *prox;
};
typedef struct elemento Elem;

//definição do nó descritor da fila
struct fila{
    struct elemento *inicio;
    struct elemento *final;
    int qtd;
};


Cada elemento guarda os dados do aluno e o ponteiro prox para o próximo nó. No último nó, prox vale NULL. O nó descritor fila tem três campos: inicio (primeiro nó), final (último nó) e qtd (quantidade de elementos). Com a fila vazia, inicio e final valem NULL e qtd vale 0.


Valores de retorno das funções:




FunçãoRetorno


cria_FilaPonteiro para a fila, ou NULL se faltar memória.


insere_Fila, remove_Fila, consulta_Fila1 se a operação foi feita; 0 se falhou (fila inválida, vazia ou sem memória).


tamanho_FilaQuantidade de elementos; 0 se a fila for NULL.


Fila_vazia1 se vazia, 0 se não vazia, -1 se a fila for NULL.


Fila_cheiaSempre 0: a fila encadeada não tem capacidade fixa.





Criação da fila


// Criando uma fila
Fila* cria_Fila(){
    Fila* fi = (Fila*) malloc(sizeof(struct fila));
    if(fi != NULL){
        fi->final = NULL;
        fi->inicio = NULL;
        fi->qtd = 0;
    }
    return fi;
}


A função aloca o nó descritor e, se a alocação funcionar, inicializa os ponteiros com NULL e qtd com 0. A figura do livro representa exatamente esse estado: inicio e final apontando para NULL.



Destruindo a fila


// Destruindo uma fila
void libera_Fila(Fila* fi){
    if(fi != NULL){
        Elem* no;
        while(fi->inicio != NULL){
            no = fi->inicio;
            fi->inicio = fi->inicio->prox;
            free(no);
        }
        free(fi);
    }
}


Percorremos todos os nós liberando cada um com free: o ponteiro no guarda o nó atual, o início avança para o próximo e só então o nó é liberado. Ao final, liberamos o nó descritor. Depois de chamar a função, o ponteiro do main não deve mais ser usado.



Consultando o início sem remover


// Consultando a fila
int consulta_Fila(Fila* fi, struct aluno *al){
    if(fi == NULL)
        return 0;
    if(fi->inicio == NULL)//fila vazia
        return 0;
    *al = fi->inicio->dados;
    return 1;
}


A função copia os dados do primeiro aluno para *al, sem alterar a fila. Retorna 0 se a fila for inválida ou estiver vazia.



Inserindo um elemento no final


// Inserindo um elemento na fila
int insere_Fila(Fila* fi, struct aluno al){
    if(fi == NULL)
        return 0;
    Elem *no = (Elem*) malloc(sizeof(Elem));
    if(no == NULL)
        return 0;
    no->dados = al;
    no->prox = NULL;
    if(fi->final == NULL)//fila vazia
        fi->inicio = no;
    else
        fi->final->prox = no;
    fi->final = no;
    fi->qtd++;
    return 1;
}


A função verifica a fila, aloca um novo nó e copia os dados. Como ele será o último, prox recebe NULL. Se a fila estava vazia, o novo nó também passa a ser o início; caso contrário, o antigo último nó aponta para ele. Por fim, atualizamos final e incrementamos qtd.



Removendo o elemento do início


// Removendo um elemento da fila
int remove_Fila(Fila* fi){
    if(fi == NULL)
        return 0;
    if(fi->inicio == NULL)//fila vazia
        return 0;
    Elem *no = fi->inicio;
    fi->inicio = fi->inicio->prox;
    free(no);
    if(fi->inicio == NULL)//fila ficou vazia
        fi->final = NULL;
    fi->qtd--;
    return 1;
}


A remoção falha se a fila for inválida ou estiver vazia. Caso contrário, guardamos o primeiro nó, avançamos o início para o próximo e liberamos o nó removido. Se não restar nenhum elemento, final também deve receber NULL, senão ele apontaria para memória já liberada.



Tamanho, fila vazia e fila cheia


// Tamanho da fila
int tamanho_Fila(Fila* fi){
    if(fi == NULL)
        return 0;
    return fi->qtd;
}

// Retornando se a fila está vazia
int Fila_vazia(Fila* fi){
    if(fi == NULL)
        return -1;
    if(fi->inicio == NULL)
        return 1;
    return 0;
}

// Retornando se a fila está cheia
int Fila_cheia(Fila* fi){
    (void)fi; // fila dinâmica nunca fica cheia
    return 0;
}


Como existe o campo qtd, o tamanho é só um retorno direto. A fila está vazia quando inicio vale NULL. Fila_cheia sempre retorna 0 porque a estrutura não tem limite pré-definido; a falta de memória é detectada pelo malloc dentro de insere_Fila.



Imprimindo a fila do início ao fim


// Imprimindo a fila, do início ao fim
void imprime_Fila(Fila* fi){
    if(fi == NULL){
        printf("Fila nao criada.\n");
        return;
    }
    if(fi->inicio == NULL){
        printf("Fila vazia.\n");
        return;
    }
    Elem* no = fi->inicio;
    int pos = 1;
    printf("--- Fila (inicio -> final) ---\n");
    while(no != NULL){
        printf("%d) Matricula: %d | Nome: %s | Notas: %.2f %.2f %.2f\n",
               pos, no->dados.matricula, no->dados.nome,
               no->dados.n1, no->dados.n2, no->dados.n3);
        no = no->prox;
        pos++;
    }
}


Um ponteiro auxiliar começa em inicio e avança por prox até chegar a NULL. A fila não é modificada. Como precisa acessar os campos internos, a função fica em FilaDin.c.







7. Programa principal


O main.c oferece um menu para testar todas as operações: inserir, remover, consultar o início, ver o tamanho, verificar se a fila está vazia ou cheia, imprimir e sair. Ele inclui apenas FilaDin.h.


main.c


#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include "FilaDin.h"

static void limpa_linha(void){
    int c;
    while((c = getchar()) != '\n' && c != EOF);
}

static void mostra_aluno(struct aluno al){
    printf("Matricula: %d\nNome: %s\nNotas: %.2f %.2f %.2f\n",
           al.matricula, al.nome, al.n1, al.n2, al.n3);
}

static int le_aluno(struct aluno *al){
    printf("Matricula: ");
    if(scanf("%d", &al->matricula) != 1) return 0;
    limpa_linha();
    printf("Nome: ");
    if(fgets(al->nome, sizeof(al->nome), stdin) == NULL) return 0;
    al->nome[strcspn(al->nome, "\n")] = '\0';
    printf("Notas (n1 n2 n3): ");
    if(scanf("%f %f %f", &al->n1, &al->n2, &al->n3) != 3) return 0;
    limpa_linha();
    return 1;
}

int main(void){
    Fila *fi = cria_Fila();
    if(fi == NULL){
        printf("Erro ao criar a fila.\n");
        return 1;
    }

    int op;
    struct aluno al;
    do{
        printf("\n=== FILA DE ALUNOS ===\n"
               "1 - Inserir\n"
               "2 - Remover\n"
               "3 - Consultar inicio\n"
               "4 - Tamanho\n"
               "5 - Fila vazia?\n"
               "6 - Fila cheia?\n"
               "7 - Imprimir fila\n"
               "0 - Sair\n"
               "Opcao: ");
        if(scanf("%d", &op) != 1) break;
        limpa_linha();

        switch(op){
        case 1:
            if(le_aluno(&al) && insere_Fila(fi, al))
                printf("Aluno inserido.\n");
            else
                printf("Falha ao inserir.\n");
            break;
        case 2:
            if(remove_Fila(fi)) printf("Elemento removido.\n");
            else printf("Fila vazia, nada removido.\n");
            break;
        case 3:
            if(consulta_Fila(fi, &al)) mostra_aluno(al);
            else printf("Fila vazia.\n");
            break;
        case 4:
            printf("Tamanho: %d\n", tamanho_Fila(fi));
            break;
        case 5:
            printf(Fila_vazia(fi) ? "Fila vazia.\n" : "Fila NAO esta vazia.\n");
            break;
        case 6:
            printf(Fila_cheia(fi) ? "Fila cheia.\n" : "Fila NAO esta cheia.\n");
            break;
        case 7:
            imprime_Fila(fi);
            break;
        case 0:
            break;
        default:
            printf("Opcao invalida.\n");
        }
    }while(op != 0);

    libera_Fila(fi);
    return 0;
}


Exemplo de saída ao escolher “Imprimir fila” com três alunos inseridos:


--- Fila (inicio -> final) ---
1) Matricula: 10 | Nome: Ana Silva | Notas: 7.00 8.00 9.00
2) Matricula: 20 | Nome: Bruno | Notas: 5.50 6.00 7.00
3) Matricula: 30 | Nome: Carla | Notas: 10.00 9.00 8.00

8. Análise de complexidade


Como a implementação mantém ponteiros para o início e o final e registra a quantidade de elementos, as operações principais não precisam percorrer a fila. Por isso, inserção, remoção e consulta do início têm tempo constante.




Inserção no finalO(1)


Remoção do inícioO(1)


Consulta do inícioO(1)




Consultar o tamanho também é O(1), pois basta retornar o campo qtd. Já a destruição e a impressão percorrem todos os nós, portanto são O(n), em que n é a quantidade de elementos.


Para lembrar: em uma fila encadeada bem implementada, manter os ponteiros inicio e final evita percorrer a estrutura a cada inserção ou remoção.






9. Erros comuns


Quase todos os erros em filas encadeadas vêm do mesmo lugar: ponteiros que não acompanham a mudança da estrutura.




Esquecer final = NULL
Ao remover o último elemento, final continuaria apontando para um nó já liberado (ponteiro “pendurado”).


Não verificar fila vazia
Remover ou consultar com inicio == NULL acessa memória inválida. Teste antes de usar.


Ignorar o retorno
malloc pode falhar. Confira o retorno de insere_Fila antes de assumir que deu certo.


Esquecer o free
Nós não liberados causam vazamento de memória. Sempre chame libera_Fila ao terminar.


Usar após liberar
Depois de libera_Fila(fi), o ponteiro não é mais válido. Não o utilize.
