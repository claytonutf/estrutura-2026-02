01 · Origem

Linus Torvalds e o projeto GNU

Linux não nasceu sozinho — ele é a peça que faltava em um projeto que já vinha de quase uma década antes.

O kernel (1991)

Linus Torvalds era estudante de Ciência da Computação na Universidade de Helsinki e desenvolvia, como projeto pessoal, um substituto para o MINIX rodando em seu computador 386. Em 25 de agosto de 1991, anunciou o projeto no grupo de discussão comp.os.minix, descrevendo-o como um hobby que não seria "grande e profissional" como o GNU.

Um mês depois, em setembro de 1991, a versão 0.01 do kernel foi disponibilizada. Em 1992, Torvalds relicenciou o código sob a GNU General Public License (GPL) — decisão que garantiu que o Linux permanecesse livre e aberto para sempre.

Universidade de Helsinki 386 PC comp.os.minix GPL v2

O projeto GNU (1983)

Oito anos antes, Richard Stallman havia fundado o projeto GNU (um acrônimo recursivo para "GNU's Not Unix") na Free Software Foundation, com o objetivo de construir um sistema operacional inteiramente livre, compatível com Unix.

Até o início dos anos 90, o GNU já tinha praticamente tudo o que um sistema precisa: compilador (GCC), shell (Bash), editores, bibliotecas e ferramentas de linha de comando. Faltava exatamente uma peça: um kernel funcional — o projeto GNU Hurd ainda não estava pronto.

O kernel Linux encaixou-se perfeitamente nessa lacuna, formando o sistema que tecnicamente deveria ser chamado GNU/Linux.

03 · Como funciona

Do hardware ao aplicativo

"Linux", tecnicamente, é só o kernel. Uma distribuição é o kernel somado a um conjunto de ferramentas, gerenciador de pacotes e, geralmente, uma interface gráfica.

Hardware
CPU, memória, disco, rede — os recursos físicos da máquina.
▲ acesso controlado por chamadas de sistema (syscalls)
Kernel Linux
Gerencia processos, memória, drivers de dispositivo e permissões. É a única parte que, tecnicamente, se chama "Linux".
▲
Ferramentas GNU / Shell
Bash, coreutils (ls, cp, grep...), gerenciador de pacotes (apt, dnf, pacman) e bibliotecas do sistema.
▲
Ambiente gráfico e aplicativos
GNOME, KDE, XFCE, navegadores, editores — tudo o que o usuário final vê e toca.

06 · Filosofia

Software livre, não necessariamente grátis

A licença GPL sob a qual o Linux é distribuído garante quatro liberdades fundamentais ao usuário — definidas pelo próprio movimento de software livre.

As quatro liberdades essenciais

  • 0. Executar o programa como desejar, para qualquer propósito.
  • 1. Estudar como o programa funciona e adaptá-lo às suas necessidades (acesso ao código-fonte).
  • 2. Redistribuir cópias para ajudar outras pessoas.
  • 3. Distribuir versões modificadas para que a comunidade toda se beneficie.

Por que isso importa

É essa filosofia que permite que centenas de distribuições diferentes coexistam, que empresas construam produtos comerciais sobre o kernel e que qualquer pessoa — inclusive um estudante universitário — possa, em teoria, propor melhorias que o mundo inteiro passa a usar.

É também o motivo pelo qual o próprio Linus Torvalds, décadas depois, continua sendo o mantenedor central do kernel, revisando contribuições de milhares de desenvolvedores ao redor do mundo.
